How to check a PDF is really redacted

28 October 2026

A page that looks redacted has passed one test, the test a human eye does in two seconds. The tests that matter take a few minutes and do not care how the page looks. Do them on the file you are about to send. Do them once on the fake US pay stub so you know what a pass and a fail feel like.

Know a string that must be dead

Pick a value you intended to remove and that you can remember. On the US dummy that value is the sample SSN 123-45-6789. It is not a real SSN. It is distinctive, so a search is unambiguous. On your own file, pick the email or the account number, not the word "total", which will appear for innocent reasons. Write it on a sticky if you have to. You cannot verify a redaction against a value you have already forgotten.

Run the dummy through the playground as in the walkthrough, with the SSN left checked, and download. Also keep a second copy where you only drew a black rectangle and did not burn the page. You want both, because the eye cannot tell them apart and the checks can.

Copy, then search, then extract

Open the burned download. Click the dark block and drag. Paste into a plain note. You want an empty paste or a paste of neighbouring text that is not the SSN. If 123-45-6789 lands on the clipboard, the text layer is alive and the block is decoration. That is the usual result on the rectangle copy, and it is the failure described in why black boxes do not hide text.

Use the viewer's search box on both files. The rectangle file should find the SSN even when your eyes only see ink. The burned file should not find it as text. Search for a fragment too, 6789, in case a tool split the number. Then select all, copy, paste. A burned page pastes nothing useful, or pastes nothing, because the page is a picture. A rectangle file pastes the whole pay stub, SSN included, which is a worse surprise than a failed search because you see every other field you forgot to cover.

If you have a terminal, pdftotext or a similar extractor is the same test without a viewer in the way. Viewers sometimes refuse to select text that is still present. Extractors do not. Strings, or opening the PDF in a text editor and searching, is cruder and still catches a secret stored in clear ASCII. It also catches secrets stored in metadata and in XML metadata packets. Do not panic at a random hit on "PDF" or on a font name. Panic at a hit on the sticky-note value.

What a passed text search does not prove

The burned pay stub can pass every text search and still show gross pay, because you left the amount visible on purpose. The digits are pixels. A person can read them. A later OCR pass can read them. Passing pdftotext means the text layer is gone, which is what you wanted for the SSN, and it means the gross pay is also gone as text even though it is there as ink. If the SSN was never detected, it is in the same boat as the gross pay: invisible to search, obvious to the eye. Look at the block. If there is no block on the SSN, the check failed no matter what search says.

White text fails the other way. Search and pdftotext succeed, the eye sees a blank, and people call it redacted because they only looked. Any check that is only visual will bless white text. Any check that is only textual will bless a scan of a passport. You need both.

HidePDF's own check is textual and narrow. After the burn it extracts text and looks for the types you hid. If it still finds one, it returns an error and does not send the PDF. The header you would have seen on a success is x-hidepdf-extractable: 0. That header means "the types we hid are not extractable as text". It does not mean "we found every secret on the page". An empty review list plus a picture of an ID card is not a pass. The OCR guide is full of that shape of failure.

The cupboards that are not the page

Open the document properties. Author, title, subject, and keywords sometimes contain the name you just spent ten minutes covering on the page. Embedded files and attachments are a second PDF inside the first. Comments and form fields hold values that never got painted. Incremental save, the way some editors write changes onto the end of the old file, can leave the previous SSN in the bytes even after the page looks clean. A rectangle almost never clears these. A new PDF built only from page images drops the original dictionary, attachments, and old revisions, because they are not on the image. The new file can still name the library that wrote it. Read properties anyway. The metadata guide is the longer version.

Check the filename. Alex-Rivera-SSN-payslip.pdf undoes a perfect burn the moment it hits an inbox. Rename to something dull before you attach. Check the email body. People hide the number in the PDF and then type it in the message so the recipient "knows which file". The message is not covered by any of the tests above.

A checklist you can reuse

  1. Work on a copy. Keep the original offline from the message you are about to send.
  2. Choose one sticky-note value that must be dead.
  3. Confirm a dark block actually sits on it in the preview, not merely that a tool said success.
  4. Copy from that spot. Paste. The value should not appear.
  5. Search the file, and run a text extractor if you have one.
  6. Read document properties, attachments, and the filename.
  7. Look at the page for values that never got a block. Assume someone will OCR whatever is still legible.
  8. Send that file only. Delete the rectangle draft so you do not attach it out of habit.

If step 4 or 5 fails, stop. You have a cover, not a redaction. Burn the page or apply a real redaction and start the checklist again. If step 7 fails, the text layer is not your problem anymore. The picture is. Cover the ink or do not send the page.

None of this makes the file suitable for a formal legal production. Those processes have their own tools and their own certificates. The checklist is for the ordinary send: a recruiter, a landlord, a client, a group chat you will regret. It takes longer to read than to do, once you have failed it once on the pay stub and seen the SSN paste out of a rectangle.
